# 用語のやさしい説明

**全部覚える必要はありません。読んでいるページに出てきた言葉だけ探してください。**

## ゲームとファイル

| 用語 | この研究での意味 |
|---|---|
| EXE／実行ファイル | ゲームを実行するプログラム。Vahren.exeは調査対象の一つです |
| DAT | このゲームの設定・イベント・命令を記述するデータ。DATという拡張子一般が同じ形式とは限りません |
| DLL | 別のプログラムから読み込んで使う部品。ゲームフォルダに置くだけで必ず機能するわけではありません |
| ソースコード | 開発者が読み書きするプログラムの文章 |
| コンパイル | ソースコードを実行・配布用などの別形式に変える作業 |
| 機械語 | CPUが実行する命令を符号化したもの |
| 逆アセンブル | 機械語を人が読めるCPU命令の表記に変えて調べること |
| 逆コンパイル | コンパイル済みプログラムを擬似的なCなどの形に直して読むこと。元のソースが完全復元されるわけではありません |
| フック | 既存処理の途中へ独自処理を挟んだり、呼び出し先を変えたりする技術 |
| プラグイン | 機能を追加する部品。別途ロードする仕組みが必要な場合があります |

## 処理の場所とデータ

| 用語 | 大まかな意味 | 注意 |
|---|---|---|
| 関数 | 「画面を開く」「値を保存する」といった処理のまとまり | 研究上の名前は原作者が付けた名前とは限らない |
| アドレス／VA | メモリ上の場所を示す数値 | ゲームや実行環境のバージョンが違えば同じ位置とは限らない |
| 16進数／0x | 数値の表し方。0x10は十進数の16 | 先頭の0xは飾りではない |
| オフセット／+0x… | 基準の場所からどれだけ離れているか | 基準が違えば指す場所も変わる |
| ポインタ | 別のデータの場所を表す値 | その数値自身がHPや経験値とは限らない |
| 構造体／フィールド | まとまったデータ／その中の項目 | 名前や意味が推定の場合もある |
| CALL | 別の処理を呼び出すCPU命令 | 静的な一覧だけでゲーム中に必ず通るとはいえない |
| 呼び出し元 | ある関数を呼ぶ側 | 呼び出し先と混同しない |
| 呼び出し先 | その関数から呼び出される側 | 同じ関数が複数箇所から呼ばれることもある |
| RET | 関数の処理を終えて戻る命令 | 関数の終端を調べる手掛かり |
| 初期化 | 処理に必要な状態を用意すること | 値を0にすることとは限らない |
| 書き戻し | 計算した結果を元のゲーム状態へ反映すること | 戦闘から戦略画面に結果を戻すことなど |
| VM／インタプリタ | DAT等の命令を解釈して実行する仕組み | CPUそのものとは別 |

例：UnitRuntime+0x90は「UnitRuntimeの基準位置から16進数0x90だけ進んだ場所」です。**この表記だけでは、何の値が入るかは分かりません。**

## 解析の言葉

| 用語 | やさしく言うと |
|---|---|
| STATIC／静的解析 | ゲームを動かさず、プログラムの命令やデータを読んで調べた |
| DYNAMIC／動的解析 | ゲームなどを実行して値や処理を観測した |
| INFERRED | 根拠をもとに推測している |
| VERIFY | 追加の確認が必要 |
| ABI／呼出規約 | 関数の引数や結果をどの場所・形式で渡すかという約束 |
| レジスタ | CPUが処理の途中で使う値の置き場。EAX、ECXなど |
| ブレークポイント | 調べたい位置で実行を停止する設定 |
| トレース | 実行された処理を順に追うこと |
| fixture／合成テスト | 試験用の入力を使った検査。ゲーム本体での実機試験とは別 |
| EVID | 公開していない出典を区別するための参照ID。信頼度の点数ではありません |
| 回帰テスト | 新しい変更が以前の動作を壊していないか調べる検査 |

GoldenやREADYは研究によって意味の異なる状態の呼び名です。**単語だけで「完成・配布可能」と判断しないでください。** [研究の読み方](reading-research.md)を参照できます。

Ghidraは逆アセンブルや逆コンパイルに使える解析ソフトです。この研究サイトを読むだけならインストール不要です。

## GitHubの言葉

| 用語 | 何をする場所・操作？ |
|---|---|
| リポジトリ | ファイルと変更履歴の保管場所 |
| Wiki | ブラウザから直接説明やメモを編集できるページ |
| Issue | 誤り、質問、調べたいことを記録する投稿 |
| Discussions | 質問・相談・意見交換の掲示板 |
| PR／プルリクエスト | ファイルの変更案を本体へ送ること |
| Fork | 自分のアカウント側に作るリポジトリのコピー |
| ブランチ | 本体と分けて作業する枝 |
| コミット | 変更を履歴として記録したまとまり |
| マージ | 別の変更を本体へ取り込むこと |
| GitHub Actions／CI | 変更やスケジュールをきっかけに処理を自動実行する仕組み |

このプロジェクトではPRが作られると、GitHub Actionsが原則として自動マージします。テスト結果は参考情報で、人間による承認は必須ではありません。形式が壊れた変更や編集の競合は自動処理できない場合があります。

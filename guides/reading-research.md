# 研究の読み方 — どこまで分かっている？

**「確認済み」という言葉だけでなく、何を、どの条件で確認したかを見ます。** 初心者の方は、難しい数式やアドレスより先に、概要と未確認事項を読んでみてください。

## 研究ページで見る4つのこと

| 見る場所 | 確認したいこと |
|---|---|
| 対象・バージョン | どのゲーム・実行ファイル・条件の話か |
| 結論・概要 | 何が分かったと言っているのか |
| 根拠・確度 | 命令を読んだのか、推測したのか、実機で観測したのか |
| 訂正・未確認事項 | 古い説明が訂正されていないか、まだ分からないことは何か |

全部揃っていなくても読んだり質問したりできます。足りない情報自体が次の研究テーマになります。

## よく出てくる確認レベル

| 表記 | まずこう読む | この表記だけでは分からないこと |
|---|---|---|
| STATIC／静的確認 | プログラムの内容を読んで確かめた | 実際のプレイで通るか、変更して動くか |
| INFERRED／推定 | 根拠から説明を考えた | 他の説明が成り立たないか |
| VERIFY／未確認 | 追加確認が必要 | 何も分かっていないとは限らない |
| DYNAMIC／実機観測 | 実際に動かして値や処理を見た | 別の条件でも同じか |
| fixture／合成テスト | 用意した試験条件で検査した | 原作でも同じ結果になるか |
| Golden／READY | 研究や試験で使われた状態の呼び名 | 全体の完成・一般配布可能とは限らない |

この説明は投稿者に新しいルールを要求するものではありません。用語の厳密な意味は個別の報告もご確認ください。

## 「研究できた」「動いた」「配布できる」は別

**仕組みが分かった？** 関係する関数や保存場所、呼び出し条件が説明できるか。

**試して動いた？** その条件で改造・拡張を動かし、結果を確かめたか。

**他の人も使える？** 配布物、導入・戻し方、対応バージョン、既知の問題が整理されているか。

関数が事典に載っていても、配布可能なDLLが完成しているとは限りません。逆に、ひとつの動作に成功しても内部のすべてを解明したとは限りません。

## 訂正は研究が進んだ記録

[Battle_ConstructSceneのページ](../reference/symbols/0048D6A0.md)には、以前の関数終端の解釈が訂正されたことが記録されています。古い数値だけを拾うと、その訂正を見落とします。

同じ目的の説明が複数あるときは、新しい記録だから自動的に正しいと判断せず、根拠と訂正理由を比較してください。

## EVIDがあれば誰でも再現できる？

EVIDは非公開の原資料を区別する参照IDです。**ID自体が研究の正しさを証明するわけでも、誰でも原資料を取得できるという意味でもありません。** [出典IDの説明](../EVIDENCE_REFERENCES.md)をご覧ください。

## GitHub Actionsのテストが成功したら研究も正しい？

自動テストはリンク・検索・ファイルの形式・サイト生成など、設定した項目を確認します。ゲームでの戦闘や経験値を実際に再現した証明ではありません。

このリポジトリでは、**テスト結果が失敗でもPRの自動統合を妨げない**方針です。自動テストが赤くても相談や訂正の投稿はできます。
